
Routes HTTP/HTTPS service to web attack technique walkthroughs. Pure router — attack content lives in per-technique files.

Ordering: P(yield)/time-cost, OSCP+-tuned. Cheap probes first (Step 1); well-known files (Step 2); active scanning (Step 3); subdomain enum only if domain-based (Step 4); deferred low-EV last (Step 5). Off-target OSINT footer-only — near-zero P(yield) on lab boxes.

---

## Setup

Per HTTP/HTTPS service on target (multiple ports = multiple walks).

`<host>` = target hostname or IP for the HTTP service. `<port>` = the HTTP/HTTPS port. `<ip>` = target IP (matches existing MW `route_<ip>.txt`). `<domain>` = target's DNS-resolvable domain (Step 4 only; skip Step 4 if target is IP-only).

Initialise decision log — append to existing `route_<ip>.txt`:

```bash
printf '\nWEB_ROUTES_TRIED (<host>:<port>):\n[<technique>] <disposition>\n' >> route_<ip>.txt
```

`<disposition>` ∈ `{APPLIED: <outcome>, INAPPLICABLE: <reason>, DEFERRED: <reason>}`

**Route flow (applies to every sub-block).** When a marker fires, walk the routed technique:

- Foothold achieved → escalate to PrivEsc ([[Linux Privilege Escalation Checksheet]] / [[Windows Privilege Escalation Checksheet]])
- Technique INAPPLICABLE at preflight → log to `WEB_ROUTES_TRIED`, next route
- All fired routes from a sub-block walked → next sub-block
- No markers fired → next sub-block

## Step 1 — Home-page reconnaissance

### 1.1 HTTP response headers

`curl -s -D - -o /dev/null http://<host>:<port>/ | grep -iE '^(Server|X-Powered-By):' || echo "NO_VERSION_HEADERS"`

Route on output:

- Line matches `Server: <product>/<version>` → `SERVER_VERSION` → edit `<product> <version>` into `services_<ip>.txt` field 5, re-run `~/scripts/searchsploit_ladder.sh` and MW [[MASTER WORKFLOW/Step 6. Vulnerability Analysis]] Pass 1 Lookup A
- Line matches `X-Powered-By: <product>/<version>` → `POWERED_BY` → same route
- `NO_VERSION_HEADERS` → 1.2

### 1.2 Favicon fingerprint

`curl -sfL http://<host>:<port>/favicon.ico | md5sum || echo "FAVICON_ABSENT"`

Compare hash against [OWASP favicon database](https://wiki.owasp.org/index.php/OWASP_favicon_database) ([[Useful Websites (Web App Pen Testing)]]).

Route on output:

- Hash matches known framework entry → `FAVICON_MATCH: <framework> <version>` → edit into `services_<ip>.txt` field 5, re-run searchsploit_ladder + MW Pass 1
- Hash present but no match in DB → `FAVICON_UNKNOWN` → log, 1.3
- `FAVICON_ABSENT` → 1.3

### 1.3 Wappalyzer extension

In browser (Wappalyzer extension installed), navigate to `http://<host>:<port>/`. Read extension panel.

Markers:

- `WAPPALYZER_STACK: <framework> <version>` — extension identifies framework/CMS/language with version
- `WAPPALYZER_STACK_NO_VERSION: <framework>` — framework identified, no version
- `WAPPALYZER_EMPTY` — nothing identified

Route:

- `WAPPALYZER_STACK` → edit into `services_<ip>.txt` field 5, re-run searchsploit_ladder + MW Pass 1
- `WAPPALYZER_STACK_NO_VERSION` → note framework for later correlation, 1.4
- `WAPPALYZER_EMPTY` → 1.4

### 1.4 HTML comments / meta generators

`curl -s http://<host>:<port>/ | grep -iE '<!--[^>]{0,200}(version|v[0-9]|generated|framework|powered)|<meta[^>]*(generator|framework)' || echo "NO_HTML_VERSION"`

Route on output:

- Line matches with version string (e.g. `<!-- Generated by X v1.2 -->`, `<meta name="generator" content="WordPress 5.4">`) → `HTML_VERSION_COMMENT: <framework> <version>` → edit into `services_<ip>.txt` field 5, re-run searchsploit_ladder + MW Pass 1
- Line matches without version → `HTML_FRAMEWORK_HINT: <framework>` → note, 1.5
- `NO_HTML_VERSION` → 1.5

### 1.5 Auth surface

In browser, walk visible auth surfaces: main login form (if any), sign-up page, forgot-password page. View source of each. Also:

`curl -s http://<host>:<port>/ | grep -oiE '<input[^>]*type=["'"'"']?password' || echo "NO_PASSWORD_INPUT_HOMEPAGE"`

Markers:

- `LOGIN_FORM: <url>` — password input on home page OR discoverable via visible navigation
- `RESET_FLOW: <url>` — password-reset flow accessible
- `MULTI_STEP_AUTH: <details>` — multi-step verification (OTP, email confirm, MFA)
- `AUTH_ABSENT` — no auth surface anywhere on visible app

Route:

- `LOGIN_FORM` → [[Authentication Bypass - Brute Force]]
- `RESET_FLOW` → [[Authentication Bypass - Logic Flaw]]
- `MULTI_STEP_AUTH` → [[Authentication Bypass - Logic Flaw]]
- `AUTH_ABSENT` → 1.6

### 1.6 Cookies

`curl -s -D - -o /dev/null http://<host>:<port>/ | grep -i '^Set-Cookie:' || echo "NO_COOKIES"`

For each cookie value, assess format:

- Plain (`admin=false`, `user_id=1`)
- Base64 (`eyJ...`, trailing `=`, decodes with `base64 -d`)
- Hash (32/40/64 hex chars → MD5/SHA1/SHA256)
- Opaque (long random-looking, no discernible format)

Markers:

- `COOKIE_PLAIN: <name>=<value>`
- `COOKIE_BASE64: <name>=<value>`
- `COOKIE_HASH: <name>=<value>`
- `COOKIE_OPAQUE: <name>=<value>` — informational only
- `NO_COOKIES` → next sub-block

Route:

- `COOKIE_PLAIN`, `COOKIE_BASE64`, `COOKIE_HASH` → [[Authentication Bypass - Cookie Tampering]]
- `COOKIE_OPAQUE` → log, no route
- `NO_COOKIES` → 1.7

### 1.7 Upload surface

`curl -s http://<host>:<port>/ | grep -oiE '<input[^>]*type=["'"'"']?file' || echo "NO_FILE_INPUT_HOMEPAGE"`

Also browse for upload features not on home page (profile picture, support ticket attachments, document submission).

Markers:

- `UPLOAD_FORM: <url>` — file input discoverable
- `UPLOAD_ABSENT` — no upload surface

Route:

- `UPLOAD_FORM` → [[File Upload]]
- `UPLOAD_ABSENT` → 1.8

### 1.8 URL parameters

`curl -s http://<host>:<port>/ | grep -oiE '(href|action)=["'"'"'][^"'"'"']*\?[^"'"'"']*' | grep -oiE '\?[^"'"'"']*' | sort -u`

Also inspect Burp Proxy history for XHR/fetch requests with parameters.

For each observed parameter, classify by shape:

Markers:

- `PARAM_FILE_SHAPE: <name>` — name ∈ {`file`, `page`, `include`, `template`, `lang`, `doc`}
- `PARAM_URL_SHAPE: <name>` — name ∈ {`url`, `server`, `redirect`, `fetch`, `dst`, `endpoint`, `src`}
- `PARAM_ID_SHAPE: <name>` — name ∈ {`id`, `uid`, `pid`} OR value numeric-sequential/base64/predictable-hash
- `PARAM_OTHER: <name>` — any other user-controlled parameter
- `NO_PARAMS` — no user-controlled parameters observed

Route:

- `PARAM_FILE_SHAPE` → [[Local File Inclusion]], then [[Remote File Inclusion]], then [[Path Traversal]]
- `PARAM_URL_SHAPE` → [[SSRF]]
- `PARAM_ID_SHAPE` → [[IDOR]]
- `PARAM_OTHER` → [[Injection]] (top-level stub routes into sub-technique per input context)
- `NO_PARAMS` → 1.9

### 1.9 Low-EV input surfaces

Browse and note:

- Search boxes, error banners, filter fields, page params that echo back → `REFLECTED_CANDIDATE`
- Comment forms, review forms, profile bio fields, ticket bodies, chat messages → `STORED_SURFACE`
- Buttons/actions that mutate state (register, redeem, transfer, one-time claim) → `STATE_ENDPOINT`

Log to `WEB_ROUTES_TRIED` as DEFERRED for Step 5 sweep — do NOT walk technique now:

```bash
printf '[step5-sweep] DEFERRED: <marker>: <location>\n' >> route_<ip>.txt
```

Route:

- `REFLECTED_CANDIDATE` → DEFERRED, Step 5 will route to [[XSS]] (Reflected branch)
- `STORED_SURFACE` → DEFERRED, Step 5 will route to [[XSS]] (Stored branch)
- `STATE_ENDPOINT` → DEFERRED, Step 5 will route to [[Race Conditions]]
- None observed → 1.10

### 1.10 Visible admin/dashboard links

Browse for visible links to `/admin`, `/dashboard`, `/settings`, `/manage`, `/console`. Also:

`curl -s http://<host>:<port>/ | grep -oiE 'href=["'"'"'][^"'"'"']*(admin|dashboard|settings|manage|console)[^"'"'"']*' | sort -u || echo "NO_ADMIN_LINK"`

For each hit, test unauth access:

`curl -s -o /dev/null -w "%{http_code}\n" http://<host>:<port>/<path>`

Markers:

- `ADMIN_LINK_UNAUTH: <path>` — HTTP 200/302 without credentials
- `ADMIN_LINK_AUTH_REQUIRED: <path>` — HTTP 401/403/redirect to login
- `NO_ADMIN_LINK`

Route:

- `ADMIN_LINK_UNAUTH` → new surface reached, re-apply Step 1 sub-blocks 1.5–1.9 against `http://<host>:<port>/<path>/`
- `ADMIN_LINK_AUTH_REQUIRED` → note the admin path for later credential re-use; if creds recovered anywhere → try against this path
- `NO_ADMIN_LINK` → Step 2

Reference: [[Step 1. Walking An Application]]

## Step 2 — Well-known files

### 2.1 robots.txt

`curl -s http://<host>:<port>/robots.txt || echo "ROBOTS_ABSENT"`

Markers:

- `ROBOTS_DISALLOW: <path>` — entries under `Disallow:`
- `ROBOTS_ABSENT`

Route:

- `ROBOTS_DISALLOW: <path>` → `curl -s -o /dev/null -w "%{http_code}\n" http://<host>:<port>/<path>`; 200/302 → new surface, re-apply Step 1 sub-blocks 1.5–1.9 against it
- `ROBOTS_ABSENT` → 2.2

### 2.2 sitemap.xml

`for f in sitemap.xml sitemap_index.xml; do printf '=== %s ===\n' "$f"; curl -s "http://<host>:<port>/$f" || echo "$f ABSENT"; done`

Markers:

- `SITEMAP_LOC: <url>` — entries in `<loc>` tags
- `SITEMAP_ABSENT` — both files absent

Route:

- `SITEMAP_LOC: <url>` → visit each; new surface → re-apply Step 1 sub-blocks 1.5–1.9
- `SITEMAP_ABSENT` → Step 3

Reference: [[Step 2. Content Discovery - Manual]]

## Step 3 — Active content discovery

### 3.1 Gobuster dir — directories

`gobuster dir -u "http://<host>:<port>" -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -r -o gobuster_dir_<ip>_<port>.txt`

### 3.2 Gobuster dir — extensions

`gobuster dir -u "http://<host>:<port>" -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt,js,json,bak,log,conf,inc,py -r -o gobuster_ext_<ip>_<port>.txt`

After both 3.1 and 3.2 complete, classify hits:

`cat gobuster_dir_<ip>_<port>.txt gobuster_ext_<ip>_<port>.txt | grep -viE 'Status:\s*(403|404)'`

Markers (grep against combined output):

- `GOBUSTER_LOGIN: <path>` — hit path matches `login`, `signin`, `admin`, `auth`
- `GOBUSTER_UPLOAD: <path>` — hit path matches `upload`, `files`, `submit`
- `GOBUSTER_API: <path>` — hit path matches `api`, `v1`, `v2`, `graphql`, `rest`
- `GOBUSTER_SENSITIVE: <path>` — hit path matches `.git`, `.env`, `.htaccess`, `backup`, `config`, `phpinfo`, `.bak`, `.old`, `web.config`
- `GOBUSTER_OTHER: <path>` — any other 200/301/302 hit
- `GOBUSTER_EMPTY` — no non-403/404 hits

Route (for any hit, first verify the real chain — gobuster's `-r` follows redirects and reports only final status: `curl -s -D - -o /dev/null http://<host>:<port>/<path>`):

- `GOBUSTER_LOGIN` → re-apply Step 1 sub-block 1.5 (auth surface) against `<path>`
- `GOBUSTER_UPLOAD` → re-apply Step 1 sub-block 1.7 (upload surface) against `<path>`
- `GOBUSTER_API` → 3.3
- `GOBUSTER_SENSITIVE` → `curl -s http://<host>:<port>/<path>`; inspect for creds/config/source; creds recovered → try against any known login form (route to sub-block 1.5 with known credentials); no creds → log, next hit
- `GOBUSTER_OTHER` → re-apply Step 1 sub-blocks 1.5–1.9 against `<path>`
- `GOBUSTER_EMPTY` → 3.3

### 3.3 Manual API route guessing

`for p in /api /api/users /api/users/admin /api/messages /api/messages/admin /api/chats /api/admin /api/v1 /api/v2 /graphql; do printf '=== %s ===\n' "$p"; curl -s -w "\n[status: %{http_code}]\n" "http://<host>:<port>$p"; done`

Markers:

- `API_DATA: <endpoint>` — 200 with JSON/data content
- `API_AUTH_HINT: <endpoint>` — 401/403 with informative error (e.g. reveals JWT header expected, Bearer scheme)
- `API_ID_PATTERN: <endpoint>` — response contains numeric IDs, UUIDs, or ID-shape fields
- `API_EMPTY` — no useful responses

Route:

- `API_DATA` → re-apply Step 1 sub-block 1.8 (URL parameters) against API endpoint; also check for [[SSRF]] if endpoint accepts URL-shape param
- `API_AUTH_HINT` → note auth mechanism; JWT/Bearer visible → [[Authentication Bypass - Cookie Tampering]] (JWT tampering branch)
- `API_ID_PATTERN` → [[IDOR]]
- `API_EMPTY` → Step 4

Reference: [[Step 4. Content Discovery - Automated Discovery (utilising GoBuster)]]

## Step 4 — Subdomain enumeration

⚠️ Skip Step 4 entirely if target is IP-only (no domain). Set `<domain>` = target's DNS-resolvable domain (e.g. `example.thm`).

### 4.1 crt.sh

Browser: `https://crt.sh` — run six searches (replace TLDs to match target):

- `%.<domain>.co.uk`
- `%.<domain>.com`
- `<domain>.co.uk`
- `<domain>.com`
- `"<domain>.co.uk"`
- `"<domain>.com"`

Markers:

- `NEW_SUBDOMAIN: <subdomain>` — subdomain in CN/SAN not previously known
- `CRT_EMPTY` — no results

Route:

- `NEW_SUBDOMAIN` → 4.5
- `CRT_EMPTY` → 4.2

### 4.2 DNSDumpster

Browser: `https://dnsdumpster.com` → input `<domain>`.

Markers:

- `NEW_SUBDOMAIN: <subdomain>`
- `NEW_DNS_HOST: <fqdn> <ip>` — additional infrastructure (out of foothold scope; augment lateral movement notes)
- `DNSDUMPSTER_EMPTY`

Route:

- `NEW_SUBDOMAIN` → 4.5
- `NEW_DNS_HOST` → log for lateral movement, 4.3
- `DNSDUMPSTER_EMPTY` → 4.3

### 4.3 Gobuster dns

`gobuster dns -d <domain> -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -o gobuster_dns_<domain>.txt`

Markers:

- `NEW_SUBDOMAIN: <subdomain>` — grep output for `Found:` lines
- `GOBUSTER_DNS_EMPTY`

Route:

- `NEW_SUBDOMAIN` → 4.5
- `GOBUSTER_DNS_EMPTY` → 4.4

### 4.4 Gobuster vhost

`gobuster vhost -u http://<host> -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt --append-domain --domain <domain> -o gobuster_vhost_<host>.txt`

If flooded by same-length responses, append `--exclude-length <n>` where `<n>` = the flood length observed.

Markers:

- `NEW_VHOST: <vhost>`
- `GOBUSTER_VHOST_EMPTY`

Route:

- `NEW_VHOST` → 4.5
- `GOBUSTER_VHOST_EMPTY` → Step 5

### 4.5 Validate and recurse

For each `NEW_SUBDOMAIN` / `NEW_VHOST` collected from 4.1–4.4:

1. If not resolvable, add to `/etc/hosts`:

    `echo "<target_ip> <subdomain>" | sudo tee -a /etc/hosts`

2. Verify HTTP alive:

    `curl -s -o /dev/null -w "%{http_code}\n" http://<subdomain>/`

3. HTTP 200/301/302 → recurse: **run this Checksheet from Step 1 against `<subdomain>`** as `<host>`.

4. Non-alive → log INAPPLICABLE, next subdomain.

Reference: [[Step 5. Subdomain Enumeration - OSINT]], [[Step 6. Subdomain Enumeration - DNS Bruteforce (GoBuster)]]

## Step 5 — Deferred low-EV route sweep

Walks routes deferred by Steps 1-4 sub-blocks that logged DEFERRED entries.

`grep 'DEFERRED' route_<ip>.txt`

For each DEFERRED entry:

- `REFLECTED_CANDIDATE: <location>` → [[XSS]] (Reflected branch)
- `STORED_SURFACE: <location>` → [[XSS]] (Stored branch)
- `STATE_ENDPOINT: <location>` → [[Race Conditions]]

Walk each. XSS foothold typically via session hijack — captured cookie feeds back to [[Authentication Bypass - Cookie Tampering]] or direct impersonation. Race Conditions typically eval/proof only — log finding, continue.

No DEFERRED entries → Exhaustion.

Steps 1-5 walked without foothold → return to [[MASTER WORKFLOW/Step 6. Vulnerability Analysis]] Pass 3, next priority service.

## Real-engagement OSINT (footer reference — not a walking step)

Off-target OSINT sources — near-zero P(yield) on OSCP+/CTF/lab boxes (synthetic targets have no public infrastructure). Walk only when engagement scope explicitly includes real production infrastructure:

- Google dorking (`site:`, `inurl:`, `filetype:`, `intitle:`)
- Wayback machine — historical paths still live
- GitHub search — public repos, leaked credentials
- S3 buckets — common suffix probing
- Shodan — additional ports, flagged CVEs

Full reference: [[Step 3. Content Discovery - OSINT]]

Any hit here: route as with any newly-discovered attack surface → re-apply Step 1 sub-blocks.
